# M10 进程级章节恢复与锁等待验收

日期：2026-09-07

## 目标与范围

在 M8 作业进程故障测试、M9 业务写入执行凭证基础上，验证已保存章节和产物版本在独立子进程故障后可以恢复。检查锁竞争是否影响租约到期判断。

本次修改只涉及 JobRegistry 的时间计算和相关测试；不调用真实模型，不消耗模型额度。

## 发现与修复

原实现的 `claim_next` 在等待 SQLite 写锁前计算租约截止时间，等待时间会侵占新租约。`heartbeat` 在实际获得写锁前计算“现在”，可能把等待期间已经过期的租约续上；`recover_expired` 也可能漏掉等待期间到期的作业。

现在三者均先获得 `BEGIN IMMEDIATE` 写锁，再读取当前时间。续租保留所有者、状态、执行凭证和到期时间的条件更新，未命中即回滚并拒绝续租。

## 验收场景

1. 子进程保存第一章和对应产物版本后被强杀。接管 Worker 等待真实的 10 秒租约自然到期，读取已保存的第一章并追加第二章。
2. 子进程停止心跳但保持执行上下文。租约自然到期后，同名 Worker 使用新凭证接管并保存第二章；在新 Worker 仍运行时释放旧处理器，旧任务记录写入、产物创建以及作业完成均被拒绝。
3. 两种场景均关闭并重新打开作业库、任务库、产物库，验证作业成功、两章完整和两个产物版本保留，无迟到内容。
4. 使用两条真实 SQLite 连接制造写锁竞争，并用可控时钟模拟等待期间经过 11 秒，分别验证领取获得完整租期、已过期心跳被拒绝、回收识别等待期间到期的作业。

测试脚本还修正了强杀后的清理逻辑：不再对已被杀死且正在等待的子进程调用 `Event.set()`，避免测试被损坏的进程同步状态阻塞。

## 验证结果

- `tests/test_job_checkpoint_process_recovery.py`：2 项通过。
- `tests/test_job_lock_timing.py`：3 项通过。
- 与既有 `tests/test_job_process_recovery.py` 合并：13 项通过，35.10 秒。
- 离线学术质量规则评测：31/31 通过。
- 全量回归：405 项通过，196.64 秒；1 个既有 FastAPI/httpx 弃用警告。

## 适用边界与下一步

这是本机 SQLite、多进程和确定性章节内容的工程验收。停止心跳由测试 Worker 控制，并未切断部署网络；不替代发布环境网络故障、压力测试或真实模型论文质量验收。

租约栅栏序列化业务写入与作业接管，不提供多个业务数据库之间的整体事务回滚。跨库中途失败仍依赖既有启动对账与恢复机制。

本阶段验收后，按路线图继续评估独立 Worker 的正式启动入口、部署持久化与发布环境故障演练；论文功能侧仍需推进全文证据绑定、交叉引用和编辑体验。
