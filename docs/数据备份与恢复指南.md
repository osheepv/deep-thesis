# 数据备份与恢复指南

M12 提供统一 `THESIS_DATA_DIR` 的停机备份和原路径恢复。命令无需模型密钥或网络，不启动 API / Worker。

## 适用范围

数据库、知识库、模板和输出文件必须全部在同一数据目录内。使用运行服务相同的存储环境变量执行命令；工具拒绝当前环境中指向目录外的存储覆盖项。工具无法发现其他进程独有的配置，操作人员必须先核对部署配置。旧版分散目录需另行迁移，不能把其中一个目录的副本称为完整备份。

先停止 API、全部 Worker 和其他写入程序，等待它们退出。`--stopped` 是操作人员的停机声明，不是自动停机或锁定机制。复制前后会比较文件清单和摘要以发现变化，但这不能替代停机，也不保证在线跨数据库事务一致性。

## 创建和检查

以下为 PowerShell 示例路径，替换为实际路径。从已安装后端的环境执行，或在 backend 目录使用模块入口：

```powershell
python -m application.backup create --data-dir 'D:\DeepThesis\data' --backup-dir 'E:\DeepThesis备份\2026-09-08' --stopped
python -m application.backup verify --backup-dir 'E:\DeepThesis备份\2026-09-08'
```

安装包也提供 `deep-thesis-backup` 同参数入口。成功退出码为 0，失败为 2。备份目标必须不存在，且不能包含数据目录或位于数据目录内。工具先写临时目录，验证成功后才发布目标目录，不覆盖旧备份。

备份由 `manifest.json` 和 `data/` 组成，清单登记原始绝对路径、每个文件的字节数与 SHA-256。验证检查缺失、多余、修改的文件，以及 SQLite 完整性；SQLite 检查在临时副本中进行，避免影响原备份的 WAL 日志。符号链接和 Windows junction 不支持。校验不是数字签名，只使用可信来源的备份。

备份包含论文正文和可能的身份数据，没有自动加密。使用受保护的备份位置，不上传公共 GitHub。API 密钥和数据目录之外的部署配置需另外保管。

## 恢复

1. 停止所有写进程，先运行 `verify`。
2. 将原数据目录保留在另一个明确路径；不要删除旧数据。恢复目标必须不存在，工具不会覆盖现有目录。
3. 使用备份清单登记的原路径恢复。当前记录包含绝对文件路径，因此不支持直接换盘、换目录恢复。

```powershell
python -m application.backup restore --backup-dir 'E:\DeepThesis备份\2026-09-08' --data-dir 'D:\DeepThesis\data' --stopped
python -m application.worker --data-dir 'D:\DeepThesis\data' --check
```

4. 只有启动对账返回 `CONSISTENT` 后再启动服务。检查任务、待审批阶段、草稿、知识库和成稿下载。对账不是论文质量审查。
5. 若恢复后异常，保持服务停止，保留恢复目录，移回先前保留的原目录后重新对账。核实恢复成功前保留旧数据和备份。
