# M13 部署入口故障恢复验收

## 验证范围

本阶段在隔离目录启动真实 Uvicorn HTTP API 和正式 `python -m application.worker` 子进程，使用共享持久化目录。模型端由本机 HTTP 故障服务提供，实际经过 DeepSeek 接入层与 SDK 的网络请求；禁止静默回退 Mock，使用虚拟密钥，不调用真实供应商。

这验证本机正式部署入口，不是已在公网发布服务器完成演练。不修改电脑网络、用户 API 密钥或现有论文，不把模拟响应当作模型质量结论。

## 故障场景

1. Worker 进入模型 HTTP 请求后强杀进程，保持 API 可用。启动同名替代 Worker，等待真实 10 秒租约自然到期，领取原作业并完成；attempt=2，不改数据库时间字段。
2. 模型服务器关闭 TCP 连接、不返回响应。SDK / 应用请求重试结束后，max_attempts=1 的作业进入 FAILED，不能伪装成功。用户通过 HTTP 重试入口重新入队，恢复模型端响应后完成同一作业。
3. 两个场景均检查同幂等键仍返回原作业、收到成功响应的用量为 20 输入 / 30 输出 Token。该计量是固定测试响应，不代表失去响应时能获知真实供应商的计费。
4. 完成后再次强杀 API 并重启，检查作业保持 SUCCEEDED、环1产物与作业绑定、候选内容仍在，FSM 保持 WAITING_APPROVAL，不自动替用户审批。

环1候选在作者选择前保存在任务记录中，因此检查实际任务产物，而非假设此时已创建正式 Artifact 版本。

## 实现与运行

本地相关回归：12 项通过，74.55 秒。新增 2 个真实进程故障场景及 1 个非法租约参数拒绝测试。

独立 Worker 新增 `--lease-seconds`，默认 120，低于 10 在打开存储前拒绝。现有内部 Worker 默认值不变。

复现命令（项目根，测试环境已有依赖）：

```powershell
backend/.venv_test/Scripts/python.exe -m pytest tests/test_deployment_fault_recovery.py tests/test_standalone_worker.py -q
```

测试只绑定 127.0.0.1，使用临时数据目录，关闭所有自身启动的进程和 HTTP 服务。每个子进程的日志保存在该测试临时目录 `process-*.log`，方便定位失败。

## 上线前仍需验证

选定真实发布环境后，按上述场景验证进程管理器重启、代理/防火墙和供应商连接中断，并检查长章节检查点、下载、磁盘空间及恢复时长。当前自动化不替代公网网络分区、系统断电、磁盘故障、认证部署或多用户压力测试，也不安装常驻服务。
