# M12 存储迁移验收

日期：2026-09-08。本报告为停机备份与恢复之后的增量交付。

## 实现

- 新增 `application.migrate_storage` 模块和 `deep-thesis-migrate-storage` 安装入口。
- 用固定 10 个数据库、3 个文件目录的来源清单，支持数据库在不同目录和不同文件名的布局；不猜测缺失来源。
- 默认在临时副本执行预检，不发布目标。`--apply` 只发布不存在的新目录，源数据保留。
- 复制数据库及侧文件，检查摘要、SQLite 完整性、必要表、未结算作业及文件引用。复制及路径处理结束后再次核对源摘要。
- 更新任务模板/成稿指针、有效 DOCX 登记和文献索引中的运行路径；不重写正文和不可变产物内容、审批历史或草稿。
- 新目录生成迁移报告，状态明确为 `COPIED_REQUIRES_RECONCILIATION`。迁移工具不会启动业务、运行模型或自动修改部署配置。

## 验证

相关回归命令：`pytest tests/test_storage_migration.py tests/test_offline_backup.py tests/test_standalone_worker.py tests/test_docx_persistent_registry.py -q --tb=short`。34 项通过，50.87 秒；随后将真实迁移执行改为独立 CLI 进程，单独复验该集成用例通过，16.25 秒。

新增 13 项测试覆盖：预检无目标副作用、源数据不变、目标覆盖拒绝、来源缺失、RUNNING/CANCEL_REQUESTED 作业阻断、必要表缺失、相对路径/嵌套目标、丢失模板登记、缺失/目录外文献引用、停机声明和迁移期间来源变化。

真实集成用例通过应用创建任务、执行环1至待审批、保存 revision=3 的未提交草稿、生成成稿和登记文献。退出进程后把数据库复制为分散目录布局，经迁移工具汇总到新目录，再隐藏原附件目录。在新进程验证：启动对账 CONSISTENT、待审批状态和环产物保留、草稿内容及版本保留、知识库文件可读、成稿经 API 下载成功。此测试不调用真实模型。

测试过程中发现 Windows 上 SQLite 上下文管理器不自动关闭连接，已改为显式关闭，避免临时目录清理和发布时文件占用。

## 范围

只支持完整登记、当前应用表结构的本机数据布局迁移，不宣称覆盖所有历史版本。缺失内存登记、从未初始化的仓储、跨操作系统迁移、数据库版本升级、在线切换及发布环境真实断网压力验收仍待处理。

没有迁移、移动或删除用户现有论文。操作与回退步骤见[存储迁移指南](存储迁移指南.md)；切换后已新增写入时，不能直接切回旧库而丢弃新工作。
