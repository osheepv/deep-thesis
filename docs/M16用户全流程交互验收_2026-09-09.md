# M16 用户全流程交互验收（2026-09-09）

## 目标

用普通用户视角检查预览版的连续写作路径，重点验证“今天停下、下次继续”以及文献不足时的可恢复交互。验收使用本地 Mock/离线模式，不把测试结果当成真实论文质量结论。

## 环境与步骤

- 通过 `scripts/run_preview.py` 启动隔离数据目录中的 API 和前端。
- 通过 Playwright CLI 操作真实浏览器，验证可访问名称、表单提交、按钮状态和刷新后的恢复界面。
- 依次执行：新建论文 → 选择研究候选 → 确认环1 → 确认环2 → 刷新页面 → 执行环3。
- 在环3没有在线检索结果时上传一份本地测试文献，登记后重新执行环3。

## 验收结果

- 新建论文表单可提交，任务标题、领域和学位级别正确进入工作区。
- 环1候选选择和环1/环2审批门正常工作，审批前后的按钮状态符合当前阶段。
- 刷新页面后显示“继续上次论文”横幅，并准确恢复到环3待处理状态。
- 环3在没有可用文献时 fail-closed，明确显示阻断原因，不允许直接进入写作。
- 上传本地文献后，离线检索模式会读取知识库中的新材料；环3不再复用先前的空结果缓存，可重新进入待审批状态。
- 环3失败卡片提供“补充文献后重试”入口，并将焦点带到文献上传控件。
- 文献上传入口改为原生按钮和隐藏文件输入，保留 PDF / Word / 题录提示，支持键盘触发。
- 账户区域使用 Deep Thesis 产品品牌文案，不再显示硬编码的个人昵称和 Pro 角色。

## 修复内容

1. 编排层只有在环3存在非空结果时才复用缓存，空结果会在新材料登记后重新执行。
2. 离线文献模式将已登记的本地文献转换为环3候选池，并保留“未在线核验”的提示。
3. 前端为文献不足提供直接补救动作，并收紧已确认阶段的候选按钮状态。
