# 存储迁移指南

M12 后续交付：将明确列出的分散 SQLite 数据库、知识库、模板和输出目录，复制到新的统一 `THESIS_DATA_DIR`。也适用于当前统一目录换路径。源文件保留，默认只预检，只有 `--apply` 才发布新目录。

## 前提与边界

- 只支持当前应用可读取、登记完整的本机 SQLite 数据。每个数据库和文件目录必须明确提供，不能靠扫描电脑猜测。
- 源数据库包括未提交草稿、用户身份、作业和审批历史；缺少数据库或旧版仅在内存中的模板/下载登记会阻断。此工具不重建用户归属，不做数据库版本升级。不应通过创建空库绕过缺失数据错误。
- 先停 API、全部 Worker 和其他写入程序。`--stopped` 表示操作人员已确认停机，工具不会自动停止进程。未结算的 RUNNING / CANCEL_REQUESTED 作业需先在旧环境走正常恢复/取消流程。
- 源内符号链接、junction、相对路径、目录外附件引用不支持；目标必须不存在，不能与任何源路径重叠。
- 需要足够磁盘空间存放临时完整副本。预检会复制并校验数据，但不改源数据或发布目标。摘要比较只能检测观察到的变化，不能替代停机。

## 来源清单

在受保护的位置准备 JSON 文件。下面都是示例路径，请按旧服务实际配置替换；不要把真实清单或数据提交到公共仓库。

```json
{
  "format": 1,
  "target": "D:/DeepThesis/data-new",
  "sources": {
    "thesis.db": "D:/OldThesis/runtime/thesis.db",
    "task_store.db": "D:/OldThesis/backend/task_store.db",
    "artifacts.db": "D:/OldThesis/backend/artifacts.db",
    "evidence.db": "D:/OldThesis/backend/evidence.db",
    "research.db": "D:/OldThesis/backend/research.db",
    "sections.db": "D:/OldThesis/backend/sections.db",
    "autosave.db": "D:/OldThesis/backend/autosave.db",
    "jobs.db": "D:/OldThesis/backend/jobs.db",
    "security.db": "D:/OldThesis/runtime/security.db",
    "docx.db": "D:/OldThesis/registry/docx.db",
    "kb": "D:/OldThesis/backend/storage/kb",
    "templates": "D:/OldThesis/backend/thesis_docx/storage/templates",
    "outputs": "D:/OldThesis/backend/thesis_docx/storage/outputs"
  }
}
```

键是新目录内固定名称，值是实际源路径，数据库文件在旧目录里可以使用不同名字。SQLite WAL/SHM/journal 侧文件会一并复制。若旧应用从未启用某仓储导致文件不存在，本工具仍返回缺失错误，需先诊断旧部署与版本，不自动视为空数据。

## 执行

在已安装后端的 Python 环境，或 backend 工作目录下执行：

```powershell
python -m application.migrate_storage --plan 'D:\Migration\plan.json' --stopped
python -m application.migrate_storage --plan 'D:\Migration\plan.json' --stopped --apply
```

安装包另提供 `deep-thesis-migrate-storage` 同参数入口。预检成功状态为 `PREFLIGHT_OK`；复制成功状态为 `COPIED_REQUIRES_RECONCILIATION`，不等于可以直接接收写入。成功退出码 0，参数或迁移失败为 2。

只更新运行所需的路径：任务自定义模板、任务成稿、有效模板/下载登记、知识库文献索引。正文、正式产物、内容哈希、审批记录和草稿保持原数据。已软删除登记与历史正文中的旧路径作为历史记录保留。迁移报告保存在新目录 `migration-report.json`。

## 验收与切换

1. 保持旧服务停止，使用新目录启动仅检查模式。清理部署中的旧存储覆盖项，使 API 与 Worker 实际使用同一个新 `THESIS_DATA_DIR`；本工具不会替你改环境配置。
2. 执行 `python -m application.worker --data-dir 'D:\DeepThesis\data-new' --check`，只有 `CONSISTENT` 才进行试用验收。启动对账可能回收租约或重放 Outbox；迁移复制本身不运行这些操作。
3. 核对待审批阶段、未提交草稿、文献附件、模板和成稿下载，再让用户继续写作。不要同时开放新旧两套写服务。
4. 给新目录做一次 M12 备份。确认验收完成前保留旧目录及旧配置。

若对账或人工验收失败，保持新服务停止，保留新目录用于分析，恢复旧配置并仅启动旧服务。此回退适用于切换后尚未开始新写入的验收阶段；若已在新环境写入内容，不能简单切回旧库，否则会遗漏新增工作，需先保存并处理差异。

跨操作系统、历史架构升级、内存登记重建、无人值守在线切换和发布环境断网压力演练不在本次验证范围。
